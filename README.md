# FixPoint / Saqta Voice Agent

Голосовой помощник вымышленной страховой компании Saqta Insurance. Требования и архитектура: `AGENTS.md`, `docs/implementation-plan.md`. Исходные данные: `case/voice_router_dataset/`.

## Backend и Streamlit

Сервер загружает официальный набор, выполняет LLM-маршрутизацию и ведёт состояние диалога.
Контракт: `POST /api/turn` принимает текст и session_id, возвращает `text`, `state`, `trace`.
Поддержан WebSocket существующего frontend. Документация: [backend-api.md](docs/backend-api.md).

Проверено на Python 3.12. Windows: из корня `powershell -ExecutionPolicy Bypass -File start.ps1`.
Скрипт создаст окружение, установит закреплённые зависимости и запустит API + Streamlit.
Либо вручную:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.lock.txt
python run.py
```

Streamlit: http://localhost:8501. API и Swagger: http://localhost:8000/docs.
`run.py` создаёт локальный `.env` из `.env.example`, если его ещё нет.
Добавьте `GROQ_API_KEY` в `.env` и перезапустите сервер. Ключ не отправлять в коммиты и комментарии.
Без ключа работает только явно обозначенный режим демонстрации с ручным выбором сценария.
Произвольные запросы не имитируют работу LLM. Для Groq выбран `llama-3.3-70b-versatile`;
модель можно изменить через `LLM_MODEL`.

Только сервер для коллеги с frontend:

```sh
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Docker Compose: `docker compose up --build` (подготовлено, локально Docker не проверен).
Все действия выполняются в изолированных тестовых данных; реальные SMS, платежи и звонки отсутствуют.

```sh
python -m pytest -q
python scripts/validate_dataset.py
python scripts/evaluate_router.py
```

Последняя команда требует ключ и вызывает реальную модель для всех 104 реплик, затем исходный
оценщик. Результаты — в `reports/`. Без ключа она завершается с явной ошибкой и не публикует
выдуманную точность. Проверены 71 локальных тестов; реальная точность и голос пока не проверены.
Подробности: [backend-validation.md](docs/backend-validation.md), [decisions.md](docs/decisions.md).

## Frontend

Простой чат на React + TypeScript + Vite. Диагностика свёрнута по умолчанию. Работа выполняется в `frontend/`; предыдущий статический дизайн не является приложением.

Требуются Node.js 22.12+ (либо 20.19+) и pnpm. Из корня репозитория:

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Открыть http://127.0.0.1:4173. При удалённом запуске распознавание требует HTTPS. Встроенные браузеры могут не поддерживать речевой сервис; проверять в обычном Chrome с доступом к микрофону и интернету.

```sh
pnpm build
pnpm test
```

### Что работает сейчас

- Текстовый чат, Enter для отправки, Shift+Enter для переноса, сброс разговора.
- Кнопка микрофона вызывает настоящий Web Speech API, показывает промежуточный текст и помещает окончательную транскрипцию в поле ввода. После проверки пользователь отправляет её в чат.
- Язык распознавания выбирается явно: `ru-RU` или `kk-KZ`. Нет обещания автоматического распознавания смешанной речи; доступность языков зависит от браузерного сервиса.
- Обработка отказа доступа, отсутствия устройства, сетевой ошибки, отсутствия речи; остановка записи и очистка при сбросе/размонтировании. Ограничение записи — 60 секунд.
- Подготовлен клиент текстового API из плана: создание сессии, WebSocket, серверные ответы и трассировка. Vite проксирует `/api` на `http://127.0.0.1:8000`.
- Сворачиваемая диагностика, выбор реплики, экспорт JSON, неизвестные задержки не заменяются нулями.
- Ответ сервера можно озвучить через браузер, если установлен голос выбранного языка; озвучивание останавливается отдельно.

### Границы текущего этапа

Backend и адаптеры LLM/STT/TTS добавлены. Для ответов на произвольные запросы нужен ключ Groq.
Без запущенного backend сообщения сохраняются только в памяти вкладки, с явной меткой.
«Подключить сервер» начинает новую серверную сессию; локальные черновые сообщения в неё автоматически не переносятся.

Web Speech API — временная проверка ввода, а не итоговая серверная голосовая интеграция. Аудио может передаваться речевому сервису браузера. Реальная речь RU/KK/mixed ещё не проверена. Нужен отдельный выбор и тест STT/TTS-провайдеров для финального MVP.

Автоматическое восстановление WebSocket, поток бинарного аудио и сквозные голосовые измерения пока не реализованы. При разрыве последняя операция не повторяется автоматически. Согласуемые поля событий описаны в `docs/frontend-integration.md`.
