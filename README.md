# Saqta Voice Router

Демо голосового AI-оператора вымышленной страховой компании Saqta Insurance для кейса HackAlem AI. Бэкенд использует LLM для выбора сценариев, ведёт контекст разговора и выполняет действия на изолированных мок-данных. Целевой каталог содержит 40 сценариев и три системных намерения. Исходные данные находятся в `case/voice_router_dataset/`.

## Что реализовано

- FastAPI принимает текстовые и аудиозапросы, управляет сессиями и возвращает ответ, состояние и трассировку выбранного сценария.
- Маршрутизатор возвращает структурированные сценарии, уверенность, язык, альтернативы и извлечённые слоты.
- Контроллер поддерживает продолжение и смену темы, очередь запросов, передачу оператору и подтверждение операций.
- Доступны 31 мок-действие, 40 сценариев и база знаний из набора. Необратимые операции выполняются только после согласия.
- React-интерфейс содержит чат, панель трассировки и предпросмотр семи экранных состояний. Предпросмотр использует тестовые данные и не проверяет серверную обработку. Подробнее: [документация предпросмотра](docs/design-preview.md).

## Запуск

Нужны Python 3.12+, Node.js 22.12+ и pnpm. В Windows самый короткий путь из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт устанавливает backend-зависимости и запускает FastAPI и Streamlit. React-интерфейс запускается отдельно:

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Откройте http://127.0.0.1:4173. API и Swagger доступны по адресам http://127.0.0.1:8000 и http://127.0.0.1:8000/docs; Streamlit — http://127.0.0.1:8501.

Для ручного запуска backend:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.venv\Scripts\python.exe run.py
```

`run.py` создаёт корневой `.env` из `.env.example`, только если файла ещё нет. Укажите ключ выбранного провайдера в `.env` и перезапустите сервер. Ключи нельзя добавлять в GitHub или отправлять в чат. Без ключа доступен только явно обозначенный демонстрационный режим; свободные пользовательские запросы не маршрутизируются настоящей LLM.

## Проверки

Из корня проекта:

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts\validate_dataset.py
.venv\Scripts\python.exe scripts\evaluate_router.py
.venv\Scripts\python.exe scripts\evaluate_dialogues.py
```

Первые две команды не требуют API-ключа. Последние две обращаются к реальной LLM: первая оценивает все 104 реплики набора, вторая запускает 10 размеченных диалогов через движок и локальные мок-действия. Если API-запрос завершается ошибкой, оценка прерывается и неполная точность не публикуется. Результаты сохраняются в игнорируемой Git папке `reports/`.

Ранее пройденные проверки и ограничения указаны в [отчёте backend](docs/backend-validation.md). Точность по 104 репликам, качество живого распознавания RU/KK/mixed и браузерное время до первого звука должны подтверждаться отдельным прогоном с настроенным провайдером и микрофоном.

## Ограничения демо

Реальные платежи, SMS, CRM и соединение с оператором не выполняются: изменения изолированы в мок-бэкенде и памяти сессии. Предпросмотр дизайна не вызывает API. Текущий микрофон рабочего frontend использует распознавание браузера и показывает текст для отправки; это не подтверждает сквозной голосовой цикл через сервер. Текущие голосовые серверные маршруты и условия проверки описаны в [контракте API](docs/backend-api.md).

Задержки по этапам отображаются в трассировке, когда они измерены. Целевые ориентиры из кейса — 500 мс для выбора сценария и 1,5 секунды от конца реплики до начала ответа; их достижение не заявляется без реального замера. Фактическое состояние проекта и оставшиеся задачи: [docs/progress.md](docs/progress.md) и [план работ](docs/implementation-plan.md).
