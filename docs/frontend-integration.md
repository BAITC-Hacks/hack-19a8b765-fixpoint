# Frontend: текущий срез и контракт интеграции

Обновление backend: текстовый контракт ниже реализован в FastAPI. Сервер на 8000,
Vite на 4173; `POST /api/sessions` и `WS /api/sessions/{id}/stream` согласованы.
Для произвольных запросов нужен API-ключ настроенного LLM-провайдера (`OPENAI_API_KEY` по умолчанию в auto-режиме). HTTP-альтернатива и точные поля ответа:
[backend-api.md](backend-api.md). Сам frontend в этом изменении не модифицировался.

Реализован простой экран по разделу 5 implementation-plan.md. Это фронтенд, не готовый голосовой агент.

## Принятые решения

- React / TypeScript / Vite и обычный CSS; без UI-библиотеки и роутера.
- Главный интерфейс: чат, микрофон, текст, RU/KK; диагностика закрыта по умолчанию.
- До появления backend реальный браузерный SpeechRecognition служит проверкой голосового ввода. Финальная транскрипция попадает в черновик; пользователь проверяет и отправляет её явно.
- `ru-RU`/`kk-KZ` задаёт язык сервису браузера, но не подтверждает его поддержку. Смешанная речь не объявляется поддержанной до реальных испытаний. Сервис может обрабатывать аудио онлайн.
- Промежуточные результаты остаются черновиком, не создают сообщения. Сброс инвалидирует обработчики старой записи.
- Отсутствие сервера отображается явно. Никаких ответов по ключевым словам, фиксированных процентов и вымышленных задержек.
- Неизмеренные задержки — null / «не измерено»; браузерное озвучивание пока не формирует метрику total.

## Ожидаемые события текстового пути

Верхний формат соответствует плану. Детали payload предложены фронтендом и требуют согласования с автором backend до интеграции.

`POST /api/sessions` → `{ "session_id": "..." }`.

`WS /api/sessions/{id}/stream`:

```json
{"type":"text.submit","request_id":"uuid","payload":{"text":"...","language":"ru"}}
```

`event_id` — возрастающее целое число в пределах сессии. Старые/повторные события игнорируются.

```json
{"type":"assistant.text","event_id":1,"turn_id":"turn-1","payload":{"text":"Ответ сервера"}}
{"type":"trace.updated","event_id":2,"turn_id":"turn-1","payload":{"turn":1,"transcript":"...","language":"ru","scenarios":[],"alternatives":[],"reason":"...","slots":{},"actions":[],"latency_ms":{"total":null}}}
{"type":"turn.completed","event_id":3,"turn_id":"turn-1","payload":{"closed":false}}
```

`closed: true` завершает разговор. `assistant.text` содержит полный текст; повторное событие для одного turn_id заменяет текст, не добавляет дубликат. `trace.updated.payload` содержит TurnTrace непосредственно. В actions backend должен явно передавать preview/execute, outcome и сведения о мок-переводе; UI показывает JSON без переинтерпретации.

`DELETE /api/sessions/{id}` закрывает старую сессию. На сбросе/размонтировании клиент прекращает микрофон и звук; освобождение серверной сессии при закрытии вкладки best effort, серверу всё равно нужен TTL.

После разрыва повторного исполнения нет. Переподключение с восстановлением snapshot, поток audio.start/binary/audio.end и playback.started/failed — следующие интеграционные этапы, сейчас не реализованы. Новый серверный разговор заменяет локальную историю только после успешного открытия WebSocket.

## Ручная приёмка голоса

1. Открыть localhost в обычном Chrome. До нажатия доступ к микрофону не запрашивается.
2. Нажать «Начать говорить», разрешить доступ. Произнести собственную RU-реплику. Проверить partial, финальный черновик, ручное завершение и отправку.
3. Повторить с Қазақша и смешанной фразой. Записать фактические результаты, не считать переключатель доказательством поддержки.
4. Проверить запрет микрофона, отсутствие речи, сеть, сброс во время записи, закрытие страницы. Индикатор браузера должен погаснуть после завершения.
5. После интеграции backend проверить ответ, trace и озвучивание на обоих языках.

Документация: https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition, https://vite.dev/guide/.
