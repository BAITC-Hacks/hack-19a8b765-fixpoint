## Что запущено

- `tests/test_scenario_paths.py`: по одному конкретному пути для каждого из 40 бизнес-сценариев, три системных намерения и проверка полноты матрицы. Решения маршрутизатора подаются как фикстуры: это проверяет контроллер и мок-бэкенд, а не качество LLM или STT.
- Для 12 сценариев с необратимым действием проверены preview без изменения данных, явное согласие, действие ровно один раз и итоговая запись или бронь в моках. Для SC05 проверен честный отказ при отсутствующем правиле перерасчёта. Для SC16 проверен отказ при подстановке полиса жилья вместо полиса от несчастного случая; подходящего полиса в исходном моке нет.
- Backend: `.venv\Scripts\python.exe -m pytest -q` — **118 passed**, одно предупреждение зависимости Starlette/httpx.
- Frontend: `pnpm test` — **15 passed**; `pnpm run build` — успешно. Эти команды запускались после изменений; параллельные изменения frontend в общем рабочем дереве не входят в сценарный анализ.
- Маршрутизатор: `.venv\Scripts\python.exe scripts/evaluate_router.py --delay 0.2` — 104 реальных вызова OpenAI `gpt-4o-mini`. Прогнозы и трасса сохранены в `reports/predictions.json` и `reports/routing_trace.json`. Исходный оценщик посчитал метрики, но процесс завершился с кодом 1 при печати казахских строк в Windows CP1251. Затем те же прогнозы без новых API-вызовов проверены командой `.venv\Scripts\python.exe -X utf8 case/voice_router_dataset/evaluate.py reports/predictions.json case/voice_router_dataset/dev_utterances.json`; она завершилась успешно. Вывод сохранён в `reports/evaluation.txt`. Скрипт вызова оценщика исправлен для UTF-8 в будущих прогонах.

| Полное совпадение для 3 неясных реплик | 0/3 |

28 реплик не совпали полностью с эталоном. Основные повторяющиеся ошибки:

- Во всех трёх `SYS_UNCLEAR` модель выбрала конкретный сценарий вместо уточнения (U102–U104).
- В восьми многоцелевых репликах потерян один запрос; например, проверка полиса плюс смена почты (U082), страховой случай плюс список документов (U090).
- В семи одиночных репликах добавлен лишний сценарий; ещё в трёх запросах вне области услуг добавлен `SYS_UNCLEAR`.
- Четыре одиночных запроса выбрали неверный сценарий (U026, U032, U035, U044).
- Три запроса завершились ошибкой разбора значений слотов из ответа LLM (U004, U007, U023); действия при этом не выполнялись.

Показатели ниже внутреннего ориентира 95% для первого сценария и полного совпадения. Оценщик не проверяет язык ответа, порядок намерений после первого, слоты, действия, голос и безопасность подтверждений.

## Найденные и исправленные дефекты

1. Идентификатор подтверждённой операции передавался следующему действию (`send_sms`). Полис/заявление уже создавались, но ход возвращал `action_error`. Идентификатор теперь используется только для того действия, которое было показано в preview.
2. `create_claim` принимал полис другого продукта: SC16 мог создать заявление о травме по полису жилья. Теперь тип полиса проверяется до записи.
3. SC10 и SC15 исполняли мок-передачу, но возвращали `completed`; теперь возвращают `handoff`.
4. Исправлен UTF-8 вызов эталонного оценщика на Windows без изменения `evaluate.py` или исходного датасета.
