# Saqta — диалоги для ручной проверки

Подготовлено 23.09.2026. Расчётная дата всех разговоров: **1 октября 2026 года**.

Это **ожидаемые диалоги для проверки**, а не запись успешного прогона приложения. Формулировки бота могут отличаться, но факты, подтверждения и результаты действий должны совпадать по смыслу. Порядок уточнений может меняться; уже сообщённые данные повторно спрашивать не нужно. Каждый ответ бота содержит один вопрос за раз.

Читайте вслух строки **Клиент**, сравнивайте ответ со строкой **Бот**. Основные примеры написаны на русском; дополнительные проверки казахского и смешанной речи находятся в конце. При необходимости явно попросите отвечать на русском, если профиль клиента предпочитает казахский.

Каждый самостоятельный кейс начинайте в новой сессии. Исключение — явно связанные цепочки, например SC13 → SC20. Все персональные данные синтетические. Госномера `482KMA02`, `111AAA01`, новый телефон `+77025550123`, название «Тест Компания» и описания новых происшествий — тестовый ввод для новых операций, а не существующие записи.

Значения в квадратных скобках, например **[номер нового заявления]**, подставляются из фактического результата действия. Их нельзя выдумывать или читать буквально. Итоговые реплики «создано», «отправлено», «изменено» допустимы только после успешного соответствующего мока. SMS, почта и передача оператору в этом приложении демонстрационные; реальной отправки или соединения нет.

При озвучивании повторных персональных данных бот маскирует их; полные значения в репликах клиента приведены для ввода. Отказ, ошибка или неподдержанный путь не засчитываются как успешное выполнение операции.

## Что фиксировать после прогона

Для каждого кейса запишите: язык и способ ввода, фактические реплики, выбранные сценарии, действия и их режимы, полученные номера, итог в моке, обнаруженную ошибку. Статусы: «пройден», «ошибка», «заблокирован отсутствием данных», «не запускался».

В трассировке после каждого хода должны быть transcript, language, scenarios, alternatives, reason, slots, actions и latency_ms. Голосовой результат проверяется микрофоном и фактическим воспроизведением; текстовый успех не доказывает работу голоса. Неизмеренную задержку не считать нулевой.

Этот набор даёт по одному основному разговору на каждый ID и дополнительные ветки. Он не заменяет полный негативный прогон, проверку всех ошибок провайдеров, сетевых повторов, изоляции сессий и оценку 104 dev-реплик. SC05 содержит ограничение перерасчёта, SC16 — отрицательный путь из-за отсутствия нужного полиса; они не доказывают успешное выполнение соответствующих операций.
