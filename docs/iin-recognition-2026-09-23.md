# Проверка распознавания ИИН — 2026-09-23

Пользователь привёл фактический транскрипт после вопроса об ИИН водителя:

> Девяносто один ноль пять двенадцать, тридцать ноль четыре пятьдесят шесть.

Это ровно `910512300456`. До исправления STT возвращал числительные словами, а маршрутизатор зависел от того, соберёт ли LLM 12 цифр. В синтетическом голосовом пробеге казахский STT также однажды пропустил повторный «нөл»; восстановить отсутствующую в транскрипте цифру без догадки нельзя.

Изменения:

- Для `gpt-transcribe` добавлены контекст ИИН/ЖСН, ключевые слова и оба ожидаемых языка RU/KK. API по-прежнему может возвращать числа словами.
- Консервативный нормализатор собирает последовательности числительных RU/KK и групп арабских цифр только в полные 12-значные ИИН. Он обрабатывает пример пользователя, цифры по одной, распространённые русские и казахские десятки, некоторые казахские варианты записи STT. Пропущенные цифры не дополняются.
- Когда диалог ожидает ИИН или реплика явно содержит «ИИН/ЖСН», маршрутизатор сверяет слот с исходным транскриптом. Полное значение из транскрипта заменяет возможную ошибку LLM; при неполном значении догадка LLM удаляется и бот переспросит. Исходный транскрипт остаётся в истории/трассировке.

Проверки:

- `tests/test_identifiers.py`: фактический пример пользователя, RU/KK, группы цифр, два водителя, неполный ИИН, заполнение слота и полный расчёт ОГПО 38 000 тенге.
- `python -X utf8 scripts/probe_iin_stt.py`: синтетический RU голос с фактической фразой пользователя → STT словами → нормализатор `910512300456`. Для синтетического KK голоса один из повторных нулей был пропущен STT, поэтому нормализатор вернул пустой результат вместо вымышленного ИИН.
- `python -X utf8 scripts/probe_iin_route.py`: реальная LLM на фактическом транскрипте выбрала SC01 и `drivers_iin=["910512300456"]`.
- Живой локальный API: вопрос «Посчитайте ОГПО для легковой машины в Алматы» → запрос ИИН; фактический транскрипт пользователя следующим ходом → SC01 завершён, `drivers_iin=["910512300456"]`, цена 38 000 тенге.
- Полный локальный набор: 135 backend-тестов, 15 frontend-тестов и production-сборка прошли на момент проверки.

Ограничение: физический микрофон пользователя недоступен для автоматического прогона. Если STT пропускает цифру в самом транскрипте, система переспросит; нужны реальные RU/KK записи с шумом и паузами для оценки качества.
